# Domain docs

Before domain work, read the root `GLOSSARY.md` and relevant ADRs under `docs/adr/`. If a `GLOSSARY-MAP.md` exists, follow it to the relevant context glossary.

Use glossary terms consistently in issues, code, and explanations. If code and glossary disagree, surface the mismatch. If a proposal conflicts with an ADR, identify the ADR and explain the conflict before changing the decision.

Keep `GLOSSARY.md` limited to domain terms and definitions. Record an ADR only for a decision that is hard to reverse, surprising without context, and made by choosing among real alternatives.
