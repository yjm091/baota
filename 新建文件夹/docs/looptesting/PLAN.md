## 3. 角色与典型旅程

- 顾客（首次使用）：冷启动 → 选择空桌 → 点菜/改数量 → 提交批次 → 选择模拟支付 → 查看本桌订单。
- 顾客（回访/易误操作）：重启后重新选桌；加入占用桌；未付款从订单页重试；重复/取消支付；加点形成第二批；未上齐时尝试结束桌次。
- 前台：尝试确认未付款订单（应拒绝）；确认已付款批次；逐道确认已备菜品上桌。
- 后厨：逐道开始制作和标记备好；尝试越权确认付款/上桌（应拒绝）。
- 管理员：菜单、桌台维护与订单总览。

## 4. 场景设计

| 功能 | 正常路径 | 边界值 | 错误输入/误用 | 取消/刷新/恢复 | 注意细节 |
|---|---|---|---|---|---|
| 选桌 | 显示 1–8 桌并选择 | 不可用桌/空列表 | 缓存桌号失效 | 冷启动、刷新、占用桌确认 | 每次新访问先选桌 |
| 点餐提交 | 加菜并创建一批 | 数量上限、空购物车 | 下架/售罄菜、重复提交 | 提交失败后购物车保留 | 服务器快照金额 |
| 模拟支付 | 三种方式各完成一批 | 多批订单金额隔离 | 非法方式、重复付款 | 取消/返回后订单待付，可重试 | 显示不真实扣款 |
| 本桌订单 | 查看批次/支付/菜品状态 | 多订单、部分退菜 | 无桌号/桌次过期 | 返回、刷新、重启 | 不暴露其他顾客身份 |
| 前台 | 已付后确认；逐道上桌 | 多菜部分完成 | 未付确认、后厨角色冒用 | 重试状态刷新 | 付款与出餐状态分离 |
| 后厨 | 每道菜制作/备好 | 多菜不同进度 | 顾客/前台调用后厨动作 | 重复标记、错误顺序 | 后厨不能确认已上桌 |
| 结束本桌 | 全付且全上桌后结束 | 一批未付/一道未上桌 | 提前结束、重复结束 | 结束后返回选桌 | 云端必须重新校验 |
| 管理端 | 员工登录与工作台状态处理 | 窄屏、空数据 | 错误凭据、角色越权 | 刷新/会话过期 | 必须在真实 Web UI 回归 |
